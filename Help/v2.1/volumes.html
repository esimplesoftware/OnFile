Onfile Help · Volumes

Volumes

A volume is one indexed root: a fixed local drive or a network share.

Add local

Pick a fixed drive that is not already in the list. NTFS can live-update. Any other named file system is Scan only: folder walk, no change journal. A drive with no file system name cannot be added. Removable/USB drives are not listed.

Add remote

Enter a UNC path such as \\server\share, click Probe, then OK if the share is reachable. Network volumes do not get live update. Scan them again when that tree changes, or set a schedule.

Volume menu

Right-click a volume, or use the Volumes menu:

  • Scan now — rebuild the index for that volume from disk.
  • Schedule — remote shares and scan-only volumes. See below.
  • Cancel scan — stop the scan that is running on this volume.
  • Pause — leave the index on disk but do not search it and do not live-update.
  • Resume — search again. An NTFS volume can live-update again.
  • Index filters — include and exclude folders.
  • Move up / Move down — change the list order.
  • Remove — delete that volume’s index rows.

Rebuild index (Tools) scans volumes again. Use it after changing filters or if results look wrong.

Icons

The first column is a status icon. Hover it for a short explanation.

Local drives:

  • Indexed — ready to search.
  • Paused — you turned it off.
  • Needs attention — not scanned yet, stale, missing, or the last scan failed. The tip shows the reason.

Clicking a local icon does nothing. Remote shares use a clock instead:

  • Off — no schedule.
  • On — a scan is scheduled.
  • Warning — the last scheduled attempt could not run. Open Schedule and read Messages.

Click a scan-only or remote clock to open Schedule.

Schedule a remote scan

Choose Schedule on a network share. Onfile must be running for a scheduled scan to start.

  • Off — no automatic scan.
  • Daily — every day at the chosen time. Weekday and Every N days are not used.
  • Weekly — the chosen weekday at the chosen time. Every N days is not used.
  • Every N days — every N days at the chosen time, counted from the day you save. Weekday is not used. If that time today has already passed, the first run is N days out.

Fields that do not apply to the cadence are disabled. Next run shows the time Onfile will use.

Run one catch-up if the PC was off is off unless you check it. If Onfile was not running when a scan was due, and catch-up is off, that run is skipped and the next one is scheduled. Catch-up runs at most one missed scan, not every missed day.

A schedule does not run while the volume is paused. It is saved and starts again after Resume.

Scan now in the dialog saves the schedule and starts a scan immediately.

Messages keeps the newest 12 notes, such as a finished scan, a missed run, or a share that could not be reached.

States

  • Added — in the list; scan to build the index.
  • Indexing / Loading — scan or startup load in progress.
  • Synced — index ready. NTFS can live-update. Scan-only volumes stay at the last scan.
  • Catching up — applying recent disk changes.
  • Stale — run Scan now.
  • Error — drive or share missing, or the last scan failed.
  • Paused — you turned it off.

Filters

Each volume has an Include list and an Exclude list (Index filters on the volume). Put one rule per line. Case does not matter, and / works the same as \.

How a path is checked

  1. If Include is empty, the whole volume is included. If it has rules, a path must match at least one.
  2. If the path matches any Exclude rule, it is skipped. Exclude wins over Include.
  3. A rule matches the folder itself and everything inside it.

Two kinds of rules

  • Name rule (no backslash), such as node_modules. Matches any folder or file with exactly that name, at any depth. It is a whole-name match: temp does not match temp2 or mytemp.
  • Path rule (contains a backslash), such as \Windows or \Users\Pat\AppData. Matches only that location, measured from the volume root. On C:, \Windows means C:\Windows, not C:\Backup\Windows.

A trailing backslash is not needed: \Windows and \Windows\ are the same rule. The leading backslash is what matters for a single folder name. \Temp matches only C:\Temp. Temp matches every folder named Temp.

Full paths such as C:\Windows or \\server\share\Archive also work. An Exclude rule that covers the whole volume is ignored. To stop indexing a volume, pause it instead.

Examples

RuleMatches on volume C:
\WindowsC:\Windows and everything under it
\Users\Pat\AppDataOnly Pat's AppData folder
AppDataEvery AppData folder, for every user
node_modulesEvery node_modules folder on the drive
desktop.iniEvery file named desktop.ini

There are no wildcards. *.tmp and Temp* do not work.

Suggested Exclude list for the Windows drive

These hold system files, caches, and temporary files you rarely search for. Copy the lines you want into the Exclude list of your C: volume:

\Windows
\Windows.old
\$Recycle.Bin
\System Volume Information
\$WinREAgent
\Recovery
\ProgramData\Microsoft\Windows Defender
\ProgramData\Package Cache
INetCache
D3DSCache
Temp

Optional, for developers (skip if you search inside code projects):

node_modules
.git
.vs
__pycache__
  • Temp skips every folder named Temp, including AppData\Local\Temp for each user. Remove it if you keep your own files in a folder named Temp.
  • Use AppData to skip all per-user application data. It is large and mostly settings and caches, but some apps keep files there.
  • Leave \Program Files in the index if you want to find installed programs.

When changes take effect

Filters apply on the next Scan now or Rebuild index. Until then, files already in the index stay searchable. Live update applies new rules only to files created or renamed after the change.
