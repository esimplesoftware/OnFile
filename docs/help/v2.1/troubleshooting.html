Troubleshooting

Close Onfile with tray Exit before deleting files or services. Logs: %APPDATA%\Onfile\onfile.log and %LOCALAPPDATA%\Onfile\usn-helper.log.

Window gone but still running

Closing the window hides to the tray. Click the icon or press Ctrl+Shift+F. Use Exit to quit.

Hotkey does nothing

The hotkey is Ctrl+Shift+F. Another program (often an extra copy of Onfile) may already own it. End extra onfile-ui.exe in Task Manager, then start Onfile once. Do not edit the settings file to change the hotkey.

No search results

  • Type at least two characters.
  • The volume is not paused and has finished loading.
  • The list stops at 200 matches. Add more of the name, or a drive such as e:.
  • Filters may exclude that folder. Scan now after editing filters.

Stale, Error, or needs attention

The local icon shows needs attention when the volume has not been scanned, is stale, is missing, or the last scan failed. Hover the icon for the reason.

Stale — Scan now. If it returns immediately, fix live update then scan again.

Error / volume not available — drive letter gone or share offline. Reconnect, or remove and add the volume again.

Live update stays off

  • onfile-usn.exe must be next to onfile-ui.exe.
  • After load, accept the Windows prompt to install Onfile USN Helper.
  • Or elevated: onfile-usn.exe --install
  • Check with sc query OnfileUsn — should be RUNNING.

Scheduled scan did not run

  • Onfile must be running at the scheduled time. Closing the window to the tray is enough. Exit is not.
  • The volume must be a remote share or a scan-only volume, and Schedule must not be Off.
  • A paused volume does not run. Resume it.
  • If the PC was off and catch-up is not checked, that run is skipped. The Messages box records it. The next run is still scheduled.
  • If the share was unreachable, the clock shows a warning and Onfile tries again while the share is still due. It does not scan a missing share.
  • If another scan is already running, the scheduled scan waits.

Search still works while live update is off. Use Scan now when files change.

Remove a stubborn helper service

Elevated Command Prompt:

sc stop OnfileUsn
sc delete OnfileUsn
taskkill /f /im onfile-usn.exe
del "%LOCALAPPDATA%\Onfile\onfile-usn.exe"

Database or settings damaged

Exit Onfile. Rename or delete onfile.db, onfile.ini, or both, under %APPDATA%\Onfile. Start again, then add volumes and scan. Do not edit those files by hand.

If Onfile says the database key was rejected, check that onfile.db.key is still beside the index before you delete onfile.db. Without that key file the index cannot be opened. See Index encryption.
